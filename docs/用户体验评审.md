# EventChain 用户体验评审

评审日期：2026-09-08

## 体验范围

- 使用学生账号浏览赛事、票务、服务、钱包和个人中心，并读取真实 Fabric 测试网络中的余额、市场和活动数据。
- 使用组织方、核验员、运营员账号检查运营台的信息层级和权限边界。
- 在桌面、700 px 窄屏和 390 px 手机宽度下检查导航、表单、卡片和横向溢出。
- 通过有状态浏览器测试验证“登录 → 建仓 → 报名 → 领票 → 签到”主流程。真实账本只做读取，避免为了评审重置或污染现有演示数据。

## 发现并修正的问题

1. 市场或活动已经超过截止时间，页面仍显示“开放”。现根据截止时间显示“待运营方锁盘”或“报名已截止，等待抽签”，同时保留链上状态推进的职责边界。
2. 服务兑换没有显示可用 `B_paid`，未选预约时间或余额不足时仍容易误点。现显示余额、校验日期和库存，并在按钮附近给出具体原因。
3. 钱包在余额为零时仍允许进入兑换或转账操作，输入框缺少清晰标签。现按余额和收款人输入控制操作状态，并补齐可访问名称。
4. 运营台向核验员、运营员展示了无权处理的结果、证据或活动字段。现按角色裁剪表单，只保留可执行操作。
5. 窄屏导航会截断入口，运营台右侧状态块会覆盖标题。现采用两行导航，并让运营表单在窄屏改为单列。
6. Fabric 网络已有身份材料时再次执行 `network.sh up` 会重复注册并失败。现检测已有材料并复用，允许安全重复启动。
7. 网络异常时前端直接展示冗长的 gRPC 原始错误。现转换为简短中文提示，并合并重复通知。

## 仍需注意的边界

- 浏览器测试使用有状态 API 替身验证完整交互，不能替代真实 Fabric 写入链路的集成测试。
- 摄像头扫码受设备和浏览器权限影响，本轮只检查了上传入口和页面逻辑，没有覆盖所有实体摄像头。
- 跨链签到与积分发放不是原子事务，符合当前本科课程项目的取舍，但答辩时应说明失败补偿思路。
