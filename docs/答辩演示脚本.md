# EventChain 课程答辩演示脚本

> 适用于当前 V2 实现，预计 8–10 分钟。账号和权限以 scripts/seed-data.sh、Express 路由和 Fabric 链码为准；旧设计文档中的 student123 / admin123 已过时。

## 1. 一句话主线

【讲解】“EventChain 用 Hyperledger Fabric 把校园体育中的积分、预测市场、活动抽签和服务兑换串成一条可审计链路；用证书角色隔离权限，用私有数据集保护个人仓位、申请和票据。”

现场重点演示三条链路：

1. 学生建仓：能看到公开概率，但看不到其他人的精确选择和金额。
2. 承诺—揭示抽签：验证员先提交种子摘要，组织者截止后才能揭示和抽签。
3. 动态票据签到：学生领取私密票据，运营员核验 30 秒动态二维码，核销后发放 B_bonus。

## 3. 答辩前准备

### 3.1 启动系统并灌入数据

按顺序准备四个终端。reset-v2.sh --yes 会清空本地 Demo 账本、身份和用户数据，只应在答辩准备阶段执行，不要在台上执行。

终端 1，首次初始化 Fabric 网络：

~~~bash
cd ~/EventChain-For-ZJU
./scripts/reset-v2.sh --yes
~~~

终端 2，启动后端：

~~~bash
cd ~/EventChain-For-ZJU/server
cp .env.example .env   # 仅首次运行
npm install            # 仅首次运行或依赖变化后
npm start
~~~

终端 3，后端显示 server listening 后灌入 Demo 数据：

~~~bash
cd ~/EventChain-For-ZJU
./scripts/seed-data.sh
~~~

终端 4，启动前端：

~~~bash
cd ~/EventChain-For-ZJU/client
npm install            # 仅首次运行或依赖变化后
npm run dev -- --host 127.0.0.1
~~~

浏览器打开 http://localhost:5173/login，并检查：

- http://127.0.0.1:3000/api/health 返回正常。
- 登录页可以打开。
- 不要在答辩过程中重新运行 reset 或 seed。

### 3.1.1 本机终端问题与现场恢复

这台 Mac 的 shell 曾保留已经失效的 7890/7891 代理变量。它们会让本地 `curl`、CA 注册或依赖下载报 `Failed to connect to 127.0.0.1 port 7891`。若再次出现，在**当前终端**执行：

~~~bash
unset ALL_PROXY HTTP_PROXY HTTPS_PROXY all_proxy http_proxy https_proxy
curl --noproxy '*' http://127.0.0.1:3000/api/health
~~~

这只清理当前 shell 的代理变量，不会退出或重启 FlClash。若健康检查仍失败，再看对应层级：

~~~bash
docker ps --format '{{.Names}}  {{.Status}}'
lsof -nP -iTCP:3000 -sTCP:LISTEN
lsof -nP -iTCP:5173 -sTCP:LISTEN
~~~

- Fabric 容器都在、3000 不监听：进入 `server` 运行 `npm start`。
- 3000 正常、5173 不监听：进入 `client` 运行 `npm run dev -- --host 127.0.0.1`。
- 只有 CA 容器、Peer/Orderer 不在：说明首次重建未完成；下台后再运行 `./scripts/reset-v2.sh --yes`，不要在答辩中重置。
- `zsh: command not found: #` 只是把说明行 `# ...` 一起粘贴进交互式 zsh；只复制命令行，或先执行 `setopt interactivecomments`。
- 本机没有安装 Go 时无需临时安装；链码部署脚本会自动使用 `hyperledger/fabric-ccenv:2.5.15` 中的 Go。

### 3.2 创建现场建仓市场

登录活动组织者：

~~~text
账号：organizer01
密码：eventchain-organizer-2026
~~~

进入“运营台”，在“创建预测市场”填写：

~~~text
市场编号：defense-live
关联活动编号：defense-live
积分分类：篮球
结果标签：主队胜,平局,客队胜
锁盘时间：答辩结束后 1 小时
市场总额上限：2000
~~~

依次操作：

1. 点击“创建 B_bonus 市场”。
2. 在“市场动作”的“目标市场”中选择 defense-live。
3. 点击“开放”。
4. 确认下方对象列表中 defense-live 的状态为“预测开放”。

### 3.3 创建现场抽签活动

仍使用 organizer01，在“创建活动”填写：

~~~text
活动编号：defense-ticket
活动标题：答辩篮球体验活动
积分分类：篮球
容量：1
报名截止：答辩开始前 10 分钟
活动开始：答辩开始后 10 分钟
活动结束：答辩开始后 90 分钟
~~~

时间必须满足“当前时间 < 报名截止 < 活动开始 < 活动结束”。点击“创建活动草稿”，确认 defense-ticket 状态为“草稿”。

### 3.4 验证员提交抽签承诺

退出组织者账号，登录独立验证员：

~~~text
账号：verifier01
密码：eventchain-verifier-2026
~~~

进入“运营台”：

1. 在“抽签与活动状态”中选择 defense-ticket。
2. “独立种子”输入 defense-ticket-seed-eventchain-2026。
3. 点击“承诺种子”。
4. 确认活动状态由“草稿”变成“报名中”。

必须保存完全相同的种子原文。组织者之后揭示的原文只要有一个字符不同，链码就会拒绝抽签。

### 3.5 两名学生报名

退出验证员账号，依次使用两名学生登录：

~~~text
学生一：3220100001
学生二：3220100002
共同密码：eventchain-student-2026
~~~

每名学生都执行：

1. 进入“票务大厅”。
2. 找到“答辩篮球体验活动”。
3. 点击“提交抽签申请”。
4. 确认“我的申请”显示“等待抽签”。

活动容量为 1、报名人数为 2，因此抽签后一定是一人中签、一人未中签。

### 3.6 报名截止后完成抽签

等到设定的报名截止时间后，重新登录 organizer01：

1. 进入“运营台”。
2. 选择 defense-ticket。
3. 独立种子输入 defense-ticket-seed-eventchain-2026。
4. 点击“揭示并抽签”。
5. 确认活动状态变成“已抽签”。

然后分别登录 3220100001 和 3220100002，查看“我的申请”：

- 记下显示“已中签”的账号，正式演示使用该账号。
- 不要提前点击“领取票据”，把领票和二维码生成留在台上。

### 3.7 准备三个浏览器会话

- 会话 A：普通浏览器窗口，登录中签学生，停在赛事市场首页。
- 会话 B：另一个浏览器或独立浏览器配置，登录 organizer01，停在“运营台”。
- 会话 C：第三个隔离会话，登录 operator01 / eventchain-operator-2026，停在“签到核验”。
- 不要用多个共享同一站点数据的窗口冒充隔离会话；否则后登录账号会覆盖先前会话。
- 关闭系统通知并放大浏览器。
- 测试摄像头权限，但不要提前核销主演示票据。
- 单机演示时，准备使用“二维码截图 → 运营员上传截图”的方式。截图含票据秘密，演示后删除，不要转发。

### 3.8 默认种子数据的时间说明

scripts/seed-data.sh 自带的 basketball-final 活动按灌数时间 T0 设置：

| 对象 | 时间 |
|---|---|
| 默认市场锁盘时间 | T0 + 2 小时 |
| 默认活动报名截止 | T0 + 4 小时 |
| 活动开始 / 结束 | T0 + 5 / 7 小时 |
| 可签到窗口 | T0 + 3 至 T0 + 9 小时 |

因此，刚灌数就对 basketball-final 执行“揭示并抽签”一定会失败。主演示使用上面单独创建的 defense-live 和 defense-ticket，不依赖默认活动等待 4 小时。

## 4. 8–10 分钟逐句脚本

### 0:00–1:00 开场：边界与架构

【页面】学生会话 A，赛事市场首页。

【讲解】“这是一个封闭校园积分 Demo。A、B_paid、B_bonus 和预测仓位都不是法币、稳定币或投资产品。前端只提供交互提示，真正授权由 Fabric 证书属性和链码再次校验。”

【指示】指向顶部姓名和“学生”角色，再指向公开概率和活动入口。

【预期】页面没有个人排行榜，也不展示其他人的精确仓位。

### 1:00–2:15 积分生命周期与服务兑换

【操作】进入“A / B 钱包”，选择“篮球”，输入 100，点击“A → B_paid”。

【讲解】“A 是基础积分；B_paid 有 A 储备，可以兑回，默认费率 0.5%；B_bonus 来自活动奖励，不可兑回。分类钱包防止不同运动场景的积分混用。”

【预期】A 可用额减少 100，篮球 B_paid 增加 100。

【操作】进入“服务兑换”，选择未来时间，兑换“篮球馆 1 小时”。

【讲解】“服务只收 B_paid。组织者上架时已预存取消赔付保证金，履约和赔付规则由链码统一校验。”

【预期】提示订单已创建，B_paid 余额减少 50。

### 2:15–3:30 学生私有仓位

【操作】打开 defense-live，选择一个结果，投入 10 B_bonus，点击“确认建立仓位”。

【讲解】“公开页只展示五分钟延迟且取整的总体概率；我的精确选择和数量保存在 PlatformMSP 与 StudentMSP 的私有数据集中。”

【预期】提示“仓位已写入私有账本”，学生可用 B_bonus 减少 10。

### 3:30–5:00 抽签公平性与角色分离

【页面】切到 organizer01 会话 B 的运营台，展示 defense-ticket 已抽签。

【讲解】“抽签不由组织者单方决定。独立验证员在报名开始前提交种子的 SHA-256 承诺，组织者只能在截止后揭示相同原文。提前抽签或原文不匹配都会被链码拒绝。候选人按‘种子 + 活动 + 匿名账号’的哈希排序，不是先到先得。”

【指示】说明组织者界面没有“承诺种子”，验证员界面没有“揭示并抽签”。

【讲解】“隐藏按钮只是用户体验；路由角色中间件和链码证书属性还会分别校验，所以绕过前端也不能越权。”

### 5:00–6:30 中签学生领取动态票据

【页面】回到中签学生会话 A，进入“票务大厅”，找到“答辩篮球体验活动”。

【操作】确认申请状态为“已中签”，点击“领取票据”。

【讲解】“领票时，浏览器在本机生成随机秘密，链上保存其哈希。秘密不显示在公开页面；领取后不要清理当前浏览器站点数据。”

【预期】“我的动态票据”出现票据编号和二维码，状态为“有效”；二维码每 30 秒变化。

### 6:30–8:00 运营员核验与奖励

【页面】切到 operator01 / eventchain-operator-2026 会话 C 的“签到核验”。

【操作】扫描学生二维码；单机演示则在会话 A 截图后立即切换到会话 C，点击“上传二维码截图”并选择刚才的图片。

【讲解】“核验会检查票据秘密、30 秒时间片、票据状态和活动时间窗口。同一张票核销后不能再次使用，并向学生发放该运动分类的 B_bonus。”

【预期】页面显示“核验成功”、票据编号、签到时间和奖励状态。若财务链码暂时失败，会明确显示“签到已确认，奖励待补发”，不会把已完成签到伪装成失败。

### 8:00–9:00 结算、挑战与仲裁

【页面】赛事详情的“结算安全”时间线，或运营台市场动作区。

【讲解】“市场到期后，组织者锁盘并提交结果和证据摘要，独立验证员二次确认。学生可锁定保证金提出挑战；有争议时三名仲裁员独立投票，否则运营员临时结算。收益先进入 7 天 Pending Claim 窗口，为暂停和更正留出时间。”

【可选指示】分别展示 verifier01、operator01、arb01 账号只拥有与其职责匹配的按钮；不要为了点满按钮而破坏主演示数据。

### 9:00–10:00 收束

【讲解】“我们不把所有数据公开上链，而是公开需要多方共识的状态，把仓位、申请和票据放入授权组织的私有数据集。这是组织级隐私，不是零知识证明；授权 Peer 管理员仍在信任边界内。”

【总结】“核心不是发行可交易代币，而是用多组织身份、可验证状态机和最小化披露，降低校园活动运营对单一后台的信任。”

## 5. 常见追问短答

**为什么不用普通数据库？**

如果只有单一可信管理方，普通数据库更合适。本项目的课程假设是平台、学生和组织方需要共享可审计状态，又不希望任意一方单独改账；Fabric 在此前提下提供身份、背书和私有数据集。

**隐私数据对所有人都不可见吗？**

不是。这是组织级隐私，不是零知识证明。未授权组织拿不到私有值，但相应 Peer 的授权管理员仍属于信任边界。

**前端隐藏按钮就能防越权吗？**

不能。项目在导航、Express 角色中间件和 Fabric 链码证书属性三层校验，最终以链码权限为准。

**为什么抽签需要独立验证员？**

若种子由组织者在看到申请后自由选择，就可以反复试算有利结果。先承诺再揭示使种子提前绑定，避免组织者单方控制。

**为什么结算后还要等 7 天？**

这是纠错窗口。收益先进入 Pending Claim，期间可以因异常暂停、更正或作废，避免错误结果立即成为不可逆余额。

## 6. 失败时的台上兜底

| 现象 | 现场解释 | 立即处理 |
|---|---|---|
| 抽签提示报名仍开放 | “链码正在阻止截止前抽签。” | 不改系统时钟，切到准备好的抽签后页面或改为口述 |
| 二维码过期 | “时间片校验已拒绝旧凭证。” | 回学生页重新截图，30 秒内上传 |
| 相机权限被拒绝 | “核验支持摄像头和图片两种输入。” | 上传二维码截图 |
| 签到成功但奖励待补发 | “跨链码操作不是原子交易，系统显式记录签到并将奖励标记为可重试。” | 保留成功回执，不重复核销 |
| Fabric 或前端暂时无响应 | “链上提交需等待背书和确认，并非本地假数据切换。” | 切到已打开的下一页，不在台上重置账本 |

## 7. 演示后验证点

- 中签学生票据由“有效”变为“已核销”。
- 签到回执显示活动、票据编号和时间，但不显示票据秘密。
- 学生篮球 B_bonus 发生可见变化，或签到页清楚标记奖励待补发。
- 学生、组织者、验证员、运营员和仲裁员的运营台按钮集合不同。
- 后端日志只作为运行证据；最终业务结果以页面回读的链上状态为准。
